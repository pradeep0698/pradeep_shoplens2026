Shipped · +37% e2e

Dropped Dead Lens Tab

47s → 30s

Google Lens "products" pass was returning 0 results on every sampled production call (50/50 checks). Removed entirely — cutting SerpAPI quota in half with no loss of results.

Shipped · 2× faster

Faster AI Model (Flash)

50s → 23s

Switched object detection from Gemini 2.5 Pro to Gemini 2.5 Flash. Validated across 5 runs — all prominent items still correctly identified with no hallucinations. Slightly fewer minor items detected, but accuracy on key products is maintained.

Shipped · ~16% faster

Smarter Image Sizing

47s → 39s

Images sent to Gemini now capped at 1280 px — per Google's own recommendation. Crop quality is unaffected (uses original bytes). Reduces AI token cost and processing time.

Shipped · ~9.5% faster

Connection Reuse

68s → 61s

SerpAPI calls now share a persistent HTTP session. Previously each of up to 20 concurrent calls opened a fresh TCP/TLS handshake — eliminating that overhead for every request.

Shipped · Concurrency

Fixed Request Blocking

1 → ∞

Blocking code inside async handlers was silently limiting throughput to 1 request at a time per server instance. Fixed with proper async threading — removes the hard concurrency ceiling under load.

Shipped · Efficiency

Removed Redundant Cleanup

Eliminated synchronous GCS file deletions from the response critical path on both /analyze and /identify. The storage bucket already auto-deletes via a 1-day lifecycle rule — these were blocking calls for no benefit.

Shipped · Observability

Structured Timing Logs

Added per-stage TIMING logs (AI detection / Lens / Shopping / crop / items) to all endpoints. Future performance work no longer requires manual log digging — every bottleneck is now measured automatically.

Tested & Reverted

What We Tried & Why We Rolled Back

Conditional Lens skip: Added +25% latency — Pass 1 always ran anyway, sequentially.

Flash for descriptions: 44% speedup but misidentified crops 5/6 times. Accuracy wins over speed here.

Next Frontier: On-Device ML

Planning · Local Object Detection to Replace Cloud Round-Trips

Current Architecture

Cloud-Only Detection

Image uploaded to Google Cloud
Gemini AI processes detection remotely
20–50 s round-trip per request
Every request burns cloud + SerpAPI quota
No offline capability
→
Target Architecture

Edge + Cloud Hybrid

Lightweight model runs directly on device
Objects detected in <1 s locally, no cloud call
Cloud only invoked for complex / ambiguous items
Dramatically lower API cost per scan
Works offline or on slow connections
Implementation Roadmap
Phase 1 · Research

Model Selection

Evaluate lightweight on-device models (YOLOv8-nano, MobileNetV4, MediaPipe) against ShopLens product category distribution. Target: <50 MB model size, >85% accuracy on top 20 categories.

Phase 2 · Prototype

Fine-Tuning & Benchmarking

Fine-tune selected model on ShopLens image dataset. Benchmark latency on mid-range Android and iOS. Establish confidence threshold for "local is good enough vs. escalate to cloud."

Phase 3 · Integration

App Integration & A/B Test

Bundle model into Flutter app via TFLite / Core ML. Implement confidence-based fallback to cloud. A/B test speed perception and result quality against current cloud-only baseline.

Phase 4 · Launch

Rollout & Iteration

Gradual rollout starting with highest-traffic categories. Monitor cloud fallback rate as the KPI — goal is >70% of scans handled fully on-device with no quality degradation.

⚡

Sub-second Detection

Local inference avoids all network round-trips — first results appear before the user lifts their finger.

💰

Lower API Costs

70%+ of scans handled on-device means a proportional reduction in Gemini and SerpAPI spend per MAU.

🔒

Privacy & Resilience

No image leaves the device for routine scans. Works on poor connectivity — opens emerging-market use cases.
